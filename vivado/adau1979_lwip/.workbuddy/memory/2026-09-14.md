## ADAU1979 I2C init error 诊断（ILA + 串口联合分析）

- 现象：串口 `ADAU1979 init error, STATUS=0x0000010A step=1 ... ACK_BITS=0`，I2C_LAST_DEV=0x11/REG=0x01/DATA=0x43；ILA（design_1_ila_i2c_debug_5，触发 i2c_debug[63:0]==0Fxx…）捕获 step 0x0E→0x0F 切换。
- i2c_debug[63:0] 位定义（adau1979_capture_v1_0_S00_AXI.v L118-138）：[63:56]=init_step, [55]=busy, [54]=done, [53]=error, [52]=pd_rst, [51]=sda_i 线电平, [50]=scl_oe_n, [49]=sda_oe_n, [48:42]=last_dev, [41:34]=last_reg, [33:26]=last_data, [25:23]=ack_bits(bit0=器件地址ACK/bit1=寄存器ACK/bit2=数据ACK)。
- 解码结论：所有采样 ack_bits=0 → 器件地址即 NACK；sda_i=0 且 sda_oe_n=1（主机已释放总线）→ SDA 线恒低；pll 轮询读也 ack_error=1。
- adau_bclk/lrclk ILA 恒 0（I2S 主机为 ADAU1979，未初始化故无时钟）。
- 结论：物理层问题（SDA 无上拉/短路/接线错误/模块未供电/从机拉死总线），非协议或寄存器配置问题。
- ack_bits 语义见 i2c_master_write8.v L173（ack_bits[byte_idx]，byte_idx 0/1/2 = 器件/寄存器/数据字节）。
- 实际运行固件为 vitis_workspace/debug_/src/vitis_adau1979_vofa.c（DIAG_BUILD=20260913-ILA，'r' 触发 Reinit）。
- 约束：C:\Users\weitong\Desktop\ADAU1979\constraints\ax7020_adau1979_j11.xdc（SCL=W19/J10-pin3, SDA=W18/J10-pin4；注意文件名 j11 与注释 J10 需核实实际使用的扩展口）。

## 追加：ADDR 地址脚核实结论（重要）

- 项目文档已记录该板存在**未完成的硬件返工项**：原理图上 U1/U2 的 ADDR0/ADDR1 每脚同时装 10k 上拉 + 10k 下拉，分压≈1.65V（非法逻辑电平，且两片地址相同）。见 docs/adau1979_vivado操作步骤.md L40-56、docs/adau1979_capture_readme.md L54。
- 目标接法：U1=0x11（拆 R11.0/R12.0，留 R13.0/R14.0）；U2=0x31（拆 R11.1/R14.1，留 R13.1/R12.1）。
- 电阻↔引脚对应：R11=ADDR1 上拉(IOVDD)、R13=ADDR1 下拉(GND)、R12=ADDR0 上拉、R14=ADDR0 下拉。
- 数据手册(Rev.B Table 11)：地址 = {ADDR1,ADDR0,1,0,0,0,1}，四选一 0x11/0x31/0x51/0x71；**ADDR0/CLATCH 拉低 3 次会切到 SPI 模式，此后 I2C 永不 ACK**——1.65V 中间电平极易误触发，可解释"连器件地址都 NACK"。
- 产出核实清单：docs/adau1979_addr_strap_verify.md（含断电电阻判据表、上电电压判据表、现场记录表、返工后复测顺序）。

## 追加：R9.1 / R10.1（U2 组 I²C 上拉）是否必须贴装

- 用户现场反馈：U2 组 R9.1、R10.1 未贴装。结论：**可以空贴，功能不受影响**。
- 依据 1：R9.x/R10.x 是 SCL/SDA→IOVDD 的 2 kΩ 上拉（BOM 2kΩ 共 4 只：R9.0/9.1/10.0/10.1；原理图该处并列 SCL/SDA/R9.x/R10.x/IOVDD）。
- 依据 2（新查证）：100 Ω 的 R1~R8 全部挂在模拟输入 AIN1~AIN8（schematic_text.txt L236-284），**I²C 通路上无串联电阻**，故两组上拉确为同一对网络上的并联。
- 依据 3：IP 只引出一对 adau_scl/adau_sda（adau1979_capture_v1_0.v L22-23），约束只有 SCL=W19/SDA=W18 → U1、U2 共用一条总线。
- 等效上拉：只装一套 = 2 kΩ（1.65 mA，推荐）；两套都装 = 1 kΩ（3.3 mA，已达 I²C VOL 测试条件上限，偏紧）；都不装 = 悬空故障（对应 sda_i 恒低现象）。
- 必查项：断电测 SCL↔IOVDD / SDA↔IOVDD 电阻（2 kΩ=一套在位、1 kΩ=两套、开路=一套都没有）；若 R9.0/R10.0 已在位而空闲仍为 0 V，则查 IOVDD 是否真加到电阻上端（供电/共地/飞线）。
- 已更新 docs/adau1979_addr_strap_verify.md：新增 2.6 节、修正原「绝对不要动」的绝对化表述、修正对照片「全部已贴装」的过度断言、测量表增加 SCL/SDA 上拉两行、第 4 节排查顺序改为「先查上拉通路」。

## 追加：故障定位清单与一处重要修正（docs/adau1979_i2c_fault_tree.md）

- **修正**：ack_bits 语义经 RTL 复核（i2c_master_write8.v L187 `ack_bits[byte_idx] <= !sda_sync[1]`；L188 若 sda_sync[1] 则置 ack_error）→ **ACK_BITS=0 = 三个 ACK 位都采样到 SDA 高 = NACK**，不是「SDA 恒低」。故撤销上一轮「SDA 恒低→无上拉」的推断：ILA 采样点落在事务中，主机驱动 0 位时 sda_i=0 属正常；且 `i2c_scl_dbg = ~scl_oe_n` 只是主机驱动状态，**不是线电平**，无法判断 SCL 是否到达模块。
- 结论：故障性质是「被寻址器件不应答」，可排除「总线被从机拉死/SDA 短路」。
- 候选原因排序：① ADDR0/ADDR1 停在 1.65V（返工未做，高）② CLATCH(=ADDR0/pin19) 被拉低 3 次锁定 SPI 模式（**仅能断电恢复**，数据手册 Rev.B P24，高）③ SCL 未真正到达模块（中高）④ 接线/扩展口错误（XDC 名 j11 注释 J10，中）⑤ SA_MODE(pin9) 未拉低→standalone 模式控制口停用（中低）⑥ 模块供电/共地（低）⑦ 上拉贴装数（低）。PD/RST 时序与 IP 协议/速率已核对无误（POWERUP_WAIT=CLK_HZ/10=100ms、PLL_WAIT=20ms、I2C_HZ=100k、pd_rst 低→高 后发 I2C）。
- 原理图复核（pdf_schematic/page-1.png 高倍裁剪，crops/sch_u2_right.png）：**R9.x = SCL 上拉到 IOVDD（2k）**、**R10.x = SDA 上拉到 IOVDD（2k）**；R11.x=ADDR1 上拉(10k)、R13.x=ADDR1 下拉、R12.x=ADDR0 上拉、R14.x=ADDR0 下拉；R16.x 47k=PD/RST 上拉；R18.x/R19.x 33Ω=R18.1→SDATAOUT12、R19.1→SDATAOUT11。U2 pin9 SA_MODE 附近有接地符号（倾向 GND，需实测确认）。
- 建议改进：① adau_scl 由 OBUFT 改 IOBUF 以回读真实线电平 ② 增加 AXI「任意地址写/读」寄存器供 PS 扫 0x11/0x31/0x51/0x71 ③ 增加 bus-clear（9 个 SCL 脉冲）④ 上电时序。

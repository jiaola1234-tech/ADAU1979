# ADAU1979 I²C 初始化失败 —— 故障定位清单

修订日期：2026-09-14（第二轮）
配套文档：`docs/adau1979_addr_strap_verify.md`（地址脚返工与核实）

---

## 0. 结论摘要

本次失败的本质是：**主机在「器件地址字节」上就收到 NACK —— 被寻址的器件没有应答**，
而不是「总线被从机拉死」或「数据线接反」。

判据来自 RTL，而不是波形目测：

```verilog
// adau1979_capture_v1_0 ... /i2c_master_write8.v L181-192
ST_ACK_HIGH: begin
    scl_oe_n <= 1'b1;  sda_oe_n <= 1'b1;      // 主机释放 SCL/SDA
    if (tick) begin
        ack_bits[byte_idx] <= !sda_sync[1];   // ← 采样到低 = 1 = ACK
        if (sda_sync[1]) ack_error <= 1'b1;   // ← 采样到高 = NACK
```

- `ACK_BITS=0` → 三个字节的 ACK 位**全部采样到 SDA 为高** → 从机一个字节都没应答。
- 若 SDA 被从机拉死或对地短路，主机在 ACK 位会读到**低**，`ack_bits` 对应位将是 1。因此可排除「总线被拉死 / SDA 短路」。

> **修正（2026-09-14）**：上一轮曾据 ILA 某一采样点 `sda_i=0` 推断「SDA 线恒低 → 无上拉」。
> 该推断**予以撤回**：该采样点落在事务进行中，主机正在驱动数据位（其中包含 0 位）时 `sda_i=0` 属正常现象。
> 另外 `i2c_scl_dbg = ~adau_scl_oe_n` 只反映**主机驱动状态**，不是线上实际电平
> （`adau1979_capture_v1_0.v` L85-86），因此**无法**用现有 ILA 判断 SCL 是否真正到达模块。

## 1. 候选原因排序

| # | 候选原因 | 机理 | 现状证据 | 排除/确认方法 | 当前概率 |
|---|---|---|---|---|---|
| 1 | **ADDR0/ADDR1 停在 ≈1.65 V（返工未做）** | 1.65 V 落在数字输入禁用区（VIH=2.0 V / VIL=0.8 V），器件地址不确定，主机发的 0x11 对不上 | 原理图已注明该返工未完成，用户尚未拆件 | 上电测 pin19/pin20 电平 | **高** |
| 2 | **CLATCH 被拉低 3 次，器件锁定 SPI 模式** | 数据手册 Rev.B P24：默认 I²C；**拉低 CLATCH（=ADDR0/pin19）三次即进入 SPI 模式，且只能靠断电恢复** | ADDR0 停在 1.65 V 中间电平，极易被噪声翻转 3 次 | **先彻底断电（拔电源≥10 s）重试**；再测 pin19 电平 | **高** |
| 3 | **SCL 未真正到达模块** | 从机收不到时钟永不 ACK；而主机内部状态机不依赖外部响应，仍会走完 3 字节 → 表现与实测完全一致 | 现有 ILA 只能看主机驱动，看不到真实线电平 | 量模块侧 SCL 空闲/活动电平；断电量通断 | 中高 |
| 4 | **接线 / 扩展口错误** | 约束文件名为 `j11`、注释却写 `J10 pin3/pin4`；飞线松动、错口、SDA/SCL 互换都会导致从机收不到有效事务 | 需人工核对 | 断电量 W18/W19 引脚 ↔ 模块 H4 pin2/pin1 通断 | 中 |
| 5 | **SA_MODE(pin9) 未拉低** | 数据手册：SA_MODE 拉高到 IOVDD 即进入 standalone 模式，**控制口停用**，SCL/SDA 被复用为采样率/格式配置脚 | 原理图该脚附近有接地符号，倾向正常，但需实测确认 | 上电测 pin9，应为 0 V | 中低 |
| 6 | **模块供电 / 共地** | IOVDD 缺失 → 上拉失效；AVDD 缺失 → 器件不工作 | 与「ACK 位能读到高」略矛盾（说明线上有拉高能力） | 量 IOVDD=3.3 V、GND 通断 | 低 |
| 7 | **I²C 上拉贴装数量** | 只需全总线有一套 2 kΩ；两套并联为 1 kΩ | 原理图已确认：`R9.x`=SCL 上拉、`R10.x`=SDA 上拉，均到 IOVDD | 断电量 SCL/SDA ↔ IOVDD | 低（详见核对清单 2.6） |
| 8 | PD/RST 时序错误 | — | IP 顺序为 `PD_RST=0 → 100 ms → 1 → 100 ms → 发 I²C`（`adau1979_i2c_init.v` L42-45/228-249），ILA 中 `pd_rst=1` | — | **已排除** |
| 9 | IP 协议/速率错误 | — | 100 kHz（`I2C_HZ=100000`）、上电等待 100 ms、PLL 等待 20 ms、脚本内容与数据手册一致 | — | **已排除** |

**优先动作**：先做完地址脚返工（无论 ①②哪一条成立都必须做），返工后**把模块彻底断电 10 秒以上再上电**（清除 SPI 模式锁定状态），然后重跑 `r` 重新初始化。

## 2. 现场测试清单（按此顺序做，每步都能砍掉一整支分支）

### T1 断电量通断（先确认"线是通的"）
万用表电阻档，FPGA 排针端 ↔ 模块 H4 排针端：

| 信号 | FPGA 引脚 | 模块 H4 针脚 | 通断 | 实测 |
|---|---|---|---|---|
| SCL | W19（J10 pin 3） | pin 1 | 应通 | |
| SDA | W18（J10 pin 4） | pin 2 | 应通 | |
| PD/RST | Y14（J10 pin 11） | pin 9 | 应通 | |
| GND | 排针 GND | GND | 应通 | |

### T2 上电测直流电平（模块侧测量，最关键的 6 个点）
程序处于复位或未初始化状态时测，参考点为模块 GND：

| 测量点 | 期望值 | 实测 | 读数为期望之外的指向 |
|---|---|---|---|
| SCL（H4 pin 1）空闲 | ≈3.3 V | | 无上拉 / SCL 被拉死 / 未连通 |
| SDA（H4 pin 2）空闲 | ≈3.3 V | | 无上拉 / 被拉死 / 未连通 |
| U1 ADDR1 (pin20) | 0 V | | **≈1.65 V → 返工未做（原因①）** |
| U1 ADDR0 (pin19) | 0 V | | 同上 |
| U2 ADDR1 (pin20) | 0 V | | 同上 |
| U2 ADDR0 (pin19) | 3.3 V | | 同上 |
| U2/U1 SA_MODE (pin9) | 0 V | | **≈3.3 V → standalone 模式，控制口停用（原因⑤）** |
| PD/RST (pin6) | ≈3.3 V | | 0 V → 器件被复位中 |

> 测量位置：LFCSP 引脚间距仅 0.5 mm，**不要戳芯片引脚**；在 R11~R14、R16 焊盘或对应过孔/测试点上测。

### T3 活动状态下量 SCL 是否在跳变
保持初始化在跑（发 `r`），用示波器看模块侧 SCL；没有示波器时用万用表 DC 档：
100 kHz、占空比约 50% 时读数约为 1.4~1.7 V（在跳变），恒 0 V 或恒 3.3 V 都说明**没有时钟到达模块**。

### T4 断电重试（清除 SPI 模式锁定）
1. 拔掉模块电源（或整板断电）**≥10 秒**；
2. 上电后等 1 s 再下程序 / 释放复位；
3. 发 `r` 重新初始化，看 `ACK_BITS`。
   - 若断电后第一次能出现 `ACK_BITS=7` → 确诊原因②（CLATCH 被噪声触发锁 SPI），
     处理办法：先把 ADDR0 的电平修成确定的 0/1（返工），彻底消除中间电平。

### T5 交叉验证（用 PC 侧 I²C 工具，脱离 FPGA）
用 CH341A / CP2112 / Arduino 直接扫 `0x11 / 0x31 / 0x51 / 0x71`：
- 有任一地址 ACK → 器件与地址脚基本可用，问题在 FPGA 侧接线/驱动；
- 四个地址全 NACK → 器件侧问题（未供电 / SA_MODE / 已锁 SPI / 地址脚非法），
  先断电 10 s 再扫一遍，仍全 NACK 则返工地址脚后再扫。

### T6 返工后复测
按 `docs/adau1979_addr_strap_verify.md` 第 4 节执行。

## 3. 建议的工程改进（可显著缩短下一次闭环时间）

| 改进 | 内容 | 收益 |
|---|---|---|
| SCL 真实回读 | 把 `adau_scl` 由 `OBUFT` 改为 `IOBUF`（与 SDA 一致），使 `i2c_scl_dbg` 反映**线上实际电平** | 一次重建即可区分「SCL 未到达模块」与「到器件不应答」 |
| 软件地址扫描 | 在 AXI 寄存器中增加"任意地址/寄存器写-读"通道，PS 运行时扫 0x11/0x31/0x51/0x71 并回读 | 不必为换地址反复综合，一次 BIT 完成地址定位 |
| 总线恢复 | 增加 bus-clear：SCL 打 9 个脉冲 + STOP，再发 START | 从"从机拉死总线"状态自动恢复 |
| 上电时序 | 保证模块电源稳定后再释放 `PD/RST`（当前由 PL 控制，模块与 FPGA 同时上电时无余量） | 避免上电竞态导致的假故障 |
